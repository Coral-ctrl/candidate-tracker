# AI Usage Log

**AI tools used:** Claude Code, for planning, code suggestions and first drafts of these documents, which I then edited. I typed the changes into the project myself and committed each step.

| #   | Where (file / feature)                                         | What the AI suggested                                                                                                                                                                                        | What I did instead                                                                                                                                                                                                                                                                                                                                                                                                                      | Why                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| --- | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Project structure                                              | When I asked to reuse my previous project's **layered** structure (`controllers/`, `services/`, `routes/`…), the AI adapted it and put core candidate logic (`stages.ts`) in `utils/`.                       | Questioned the `utils/` placement, compared organising by layer with organising by feature, and chose **by feature**: `candidates/` and `summary/`, with only shared code in `config/`, `middleware/`, `utils/`. Named app folders to `backend/` and `frontend/`. Locked the structure in `CLAUDE.md`.                                                                                                                                  | There's only one main resource (candidates), so layer folders would each hold a single file. The brief wants the AI feature to be a "clearly separate, addressable module", and a `summary/` folder makes that obvious at a glance. With everything about candidates in one folder, I can walk through the whole request flow in one place. `backend/` and `frontend/` match my previous project, which makes the code easier for me to navigate and explain. |
| 2   | AI summary panel, `frontend/src/index.css`, `seedData.test.ts` | Retry and Regenerate buttons, code to protect against a rare race condition, new panel CSS, dark mode colours, and a test file for the seed data.                                                            | Asked whether every change was necessary and had the AI check the project against the brief. Cut all of these. The panel now only displays the result, and reopening a candidate retries. The app is light mode only, and 12 tests have been removed.                                                                                                                                                                                   | The brief says a working slice beats extra features and puts polish out of scope. The seed tests checked my sample data tool, not the app. Every extra is also more code I'd have to review. The trade-offs are no in-page retry, and nothing automatically checks the seed data any more.                                                                                                                                                                    |
| 3   | `candidate.validation.ts`, `candidate.service.test.ts`         | Validation that collected every problem into a `details` array, maximum lengths on names and notes, `isRecord` helper functions, and a `test.each` matrix of bad inputs with an "all problems listed" check. | Pointed out that the brief puts exhaustive error handling and edge-case polish out of scope. Validation now stops at the first problem with a single message. I removed the extra length limits and helpers, and kept a smaller set of focused tests. I kept the checks that protect correctness: required fields, valid stage and sort values, no blank notes, a 404 for unknown ids, and new candidates always starting at `APPLIED`. | A working core matters more than edge-case polish, and fewer rules means less to explain. I didn't cut everything, though: without a stage check, `?stage=HIRED` would quietly return every candidate, which is a bug rather than polish. I also kept the 50,000-character resume limit, because it protects the AI call's cost and size. The trade-off is that a user with several mistakes in the form sees them one at a time.                             |
| 4   | `summary.prompt.ts`, `runOnSeed.ts`                            | Adding "Personality traits and vague self-descriptions are not skills" to the prompt, with the claim that the vague resume would then list no skills.                                                        | Checked the claim with `npm run summary:try` instead of trusting it. The run still listed "Good with computers", so I rejected that wording. I then tried a second wording, which says what a skill is and why the list matters, and reran it. That version removed the vague skill, so I kept it and stopped tuning.                                                                                                                   | A prediction about a model isn't evidence, and only its real output counts. The examples in the prompt are deliberately not from my seed resume, so the fix doesn't just fit the test.                                                                                                                                                                                                                                                                        |
